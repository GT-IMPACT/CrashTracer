# Анализ, доказательства и маппинги

## Анализ исключений

Сохранить исходную структуру исключений, затем выделить корневое исключение, значимые stack frames и кандидатов на источник сбоя. Анализировать `cause` и `suppressed`, а не только верхнее сообщение.

Базовая атрибуция связывает классы из стектрейса с модами и JAR. Расширенная использует Mixin-конфигурации, ошибки применения, трансформеры и предшествующие события.

Каждый кандидат содержит основание: frame, связь класса с JAR, имя миксина/config или конкретную ошибку трансформации. Отчёт должен объяснять уверенность и сохранять альтернативных кандидатов. Формулу оценки и пороги нужно определить отдельно; случайные проценты не использовать.

Присутствие мода в стектрейсе — косвенный признак. Прямая связь ошибки применения с Mixin-конфигурацией и JAR сильнее, но тоже не всегда объясняет первопричину конфликта.

## Деобфускация

Локальный `MappingResolver` преобразует SRG → MCP для Minecraft 1.7.10. Хранить исходный стектрейс и результат преобразования отдельно; фиксировать источник/версию маппингов. При отсутствии соответствия оставлять исходное имя.

Нормализация стектрейсов пригодится для сравнения локальных инцидентов и устранения дубликатов. Она не должна удалять исходные данные. Конкретный набор маппингов и правила нормализации ещё не выбраны.

## Отложенный анализ

При аварии приоритет — сохранение. Деобфускация, большие графы связей и обработка bytecode выполняются после фиксации исходных материалов: при следующем запуске или локальной CLI.

`tracer-analyzer` — перспективная самостоятельная утилита для Java 8; основную логику можно писать на Kotlin. Она читает сохранённые файлы без запуска Minecraft и позволяет повторить анализ с новыми правилами/маппингами. Это последующий этап, не условие готовности v0.1.
