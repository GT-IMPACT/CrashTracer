# Архитектура и языки

Основная логика, модели данных, анализ и запись отчётов — Kotlin с совместимостью Java 8. Mixin-классы — Java. Для bootstrap и низкоуровневых адаптеров Java допустима, если это необходимо для загрузки или совместимости.

Ранняя точка входа не должна загружать Kotlin runtime раньше его доступности. Конкретную границу Java/Kotlin следует выбрать после проверки порядка загрузки Forgelin и UniMixins в сборке.

## Логические компоненты

Это границы ответственности; отдельные Gradle-модули для каждой подсистемы не обязательны.

| Компонент | Ответственность |
| --- | --- |
| `bootstrap` | Ранняя инициализация, сессия, подготовка записи |
| `capture` | Получение исключений и устранение дубликатов |
| `context` | Снимки окружения, модов, фаз FML и потоков |
| `runtime` | Ограниченная история диагностических событий |
| `compat/bettercrashes` | Опциональная интеграция с обработчиками BetterCrashes |
| `compat/unimixins` | Получение диагностических сведений UniMixins |
| `forensics` | Mixin Inspector и Transformer Inspector |
| `analysis` | Анализ исключений, атрибуция, доказательства |
| `mappings` | Локальная деобфускация |
| `report` | TXT/JSON, вложения и аварийная запись |
| `tracer-analyzer` | Перспективная локальная CLI для повторного анализа |

## Поток данных

1. Bootstrap открывает сессию и готовит минимальную запись.
2. Collectors обновляют контекст, интеграции поставляют доступные метаданные.
3. Capture связывает уведомления об одном сбое в один инцидент.
4. Writer сохраняет исходные данные независимо от успеха анализа.
5. Analyzer добавляет выводы и доказательства; writer формирует читаемый отчёт.

Ядро работает с собственными моделями и не зависит от внутренних типов BetterCrashes или конкретной реализации Mixin.

## Контракты из обсуждения

- `CrashIntegration`: проверка доступности и подключение источника событий.
- `CrashCollector`: получение данных о сбое.
- `EvidenceProvider`: дополнительные диагностические факты.
- `MappingResolver`: разрешение имён из локальных маппингов.
- `CulpritAnalyzer`: кандидаты и основания атрибуции.
- `ReportWriter`: запись диагностических артефактов.

Имена предварительные; сигнатуры и модель данных определяются при реализации.
