# Один архив для разработчика

Игрок читает короткую сводку на экране краша, нажимает «Открыть папку с архивом»
и отправляет единственный ZIP из открывшейся папки разработчику сборки.
К сообщению достаточно добавить действия перед ошибкой.

## Экран

При установленном BetterCrashes дополняется его существующий GuiProblemScreen:
сводка заменяет длинную инструкцию об отправке ссылки, кнопка ZIP добавляется
отдельной строкой. Заголовок, кандидаты BetterCrashes, имя vanilla-report,
Open Crash Report, Upload and copy link, возврат в меню и issue tracker сохраняются.
Это относится и к GuiCrashScreen, и к GuiInitErrorScreen, который самостоятельно
создаёт кнопки без вызова базового initGui.

Без BetterCrashes перед обычным фатальным выходом Minecraft показывается
GuiCrashSummary: сводка, папка ZIP, обычный crash-report и выход. Во время этого
экрана игровые тики не выполняются, внутреннему серверу запрашивается остановка.
После закрытия продолжается штатный вывод отчёта и выход. Продолжение игры
после краша без BetterCrashes не реализовано.

Сводка использует русский или английский язык клиента. Она сообщает тип ошибки,
возможную связь с модами и следующий шаг. Низкая уверенность не обозначает
виновника. Если первопричина неизвестна, это написано прямо.

## Состав и ограничения

Путь: `crash-tracer/reports/<incident>/share/crashtracer-<incident>.zip`.
Папка share предназначена для одного архива; сырые файлы уровнем выше существуют
до успешной упаковки и проверки ZIP, после чего удаляются (начиная с rc.5).
Повторный анализ атомарно заменяет этот же ZIP, вложенных архивов нет.

- READ-ME-FIRST.txt: краткая сводка на языке клиента (ru_RU — русский,
  остальные языки — английский). При неизвестном языке используется английский.
- incident/: доступные файлы capture и анализа этого инцидента.
- session/: идентификатор, окружение и ограниченная история этой сессии.
- minecraft/: только связанный с инцидентом обычный crash-report, если сохранён.
- logs/: последние 1 MiB каждого доступного latest/FML лога той же сессии.
- CONTENTS.txt: включённые файлы и причины пропуска или усечения.

Лимит несжатых данных: maxReportBytes + 4 MiB. Обычный crash-report ограничен
2 MiB. При восстановлении старого отчёта логи более новой JVM не добавляются.
Моды, миры, конфиги и посторонние отчёты в ZIP не включаются. Из текстов
маскируются известные шаблоны credentials; произвольные личные данные в сообщениях
модов не гарантированно распознаются. Автоматической отправки нет.

Сборка идёт в фоновом потоке. Пока ZIP не готов, кнопка показывает подготовку;
при файловой ошибке доступен повтор. Если открыть папку средствами ОС не удалось,
на экране показывается путь. Предыдущий готовый архив сохраняется при ошибке
пересборки. Очистка старого инцидента удаляет и его архив.

Нативный сбой JVM, недоступная графика или краш до загрузки Tracer не гарантируют
экран. Доступные ранние/native captures анализируются при следующем здоровом
запуске либо standalone CLI, который также создаёт ZIP.

## Автономная проверка

42 JUnit-теста на Java 8, включая пять проверок ZIP/сводки: состав, ограничение
и маскирование логов, изоляция сессий, повторная сборка, квота, создание после
анализа и восстановление недостающего архива.

Отдельный reobf-клиент с BetterCrashes 1.4.7-GTNH и UniMixins 0.3.2 проверяет
наличие готовой кнопки ZIP и штатной кнопки vanilla-report, сохраняет скриншоты
игрового и стартового экранов. Отдельные пробы без BetterCrashes проверяют
собственный экран и вход в настоящий Minecraft.displayCrashReport.
Клиентские пробы входят только в opt-in fixture, не в основной JAR.

Подтверждено на локальном 0.1.0-rc.2:

- `test build`: 42 теста, failures/errors 0, Java 8.
- BetterCrashes: оба экрана, сохранённые штатные кнопки, готовый ZIP;
  проверены скриншоты в окне 854×480.
- Без BetterCrashes: собственный экран с тремя кнопками; отдельный настоящий
  displayCrashReport сохранил vanilla-report и ZIP. После программного закрытия
  экрана vanilla завершила процесс с кодом -1, поэтому Gradle этого намеренно
  аварийного прогона сообщает BUILD FAILED — это ожидаемый исход.
- `runServer`, report: запуск, создание отчёта/архива, 120 тиков, штатное
  сохранение и остановка; клиентские классы не мешают выделенному серверу.
- Standalone CLI на Java 8: ZIP создан, исходный report.json не изменился.
- В основном JAR нет классов клиентской и серверной тестовых фикстур.

При проверке состава обнаружен старый fml-server-latest.log в клиентской папке.
Добавлена нижняя граница времени лога по началу сессии; регрессионный тест и
финальный клиентский архив подтверждают исключение этого файла.

## Контекст взаимодействия — 0.1.0-rc.3

В report.json добавлено необязательное поле interaction; старые отчёты со
schemaVersion=1 читаются без изменений. Те же данные вынесены в interaction.json
и interaction.txt, оба файла входят в ZIP.

NetworkManager перехватывает обработку очереди и priority packets. Для C08
снимок делается до обработки: предмет, registry ID, класс, metadata, количество,
признак NBT, dimension, sneaking и активный контейнер. Сохраняются класс
контейнера, window ID, число слотов, выбранный индекс инвентаря и соответствующий
номер слота контейнера. При исключении делается второй снимок. Из пакета C08
записываются класс, действие RIGHT_CLICK_AIR/BLOCK, x/y/z, face, hitX/Y/Z и
идентификатор переданного предмета. Для других server-play пакетов доступны
класс и снимок игрока в момент сбоя; исходное состояние заранее не копируется.

NBT целиком, содержимое слотов/инвентарей, chat/command payload и адреса не
сохраняются. Display-name callbacks модов не вызываются: идентификация предмета
основана на registry ID и metadata. Проверяется максимум 512 слотов; неполный
просмотр не выдаётся за доказанное отсутствие выбранного слота.

Активный контекст живёт только внутри try/finally обработки пакета, в том числе
при построении CrashReport до выхода из обработчика. После выхода остаётся
ограниченный кеш из 32 снимков с weak identity исключения, без ссылок на игрока,
контейнер или пакет. Вложенность активных обработчиков ограничена восемью.
Диагностические ошибки не заменяют исходное исключение и не повторяют обработку
пакета. Контекст предыдущего пакета не используется для посторонних ошибок.

Сводка по стеку NetHandlerPlayServer/C08 объясняет сбой правого клика, отличает
внутренний сервер и сообщает Shift+ПКМ при наличии снимка sneaking. Предмет и
контейнер добавляются как контекст, без автоматического объявления их мода
виновником. Анализ отмечает смену контейнера и отсутствие выбранного слота;
для подынтерфейсов отсутствие слота может быть нормальным. Первопричина этого
NPE по одному стеку не считается доказанной.

Проверки: 45 JUnit-тестов на Java 8; регрессия формы пользовательского стека,
SRG-имя метода, совместимость старого JSON, JSON/ZIP round trip, смена контейнера
и неполный просмотр слотов. Серверная fixture пропускает C08 через настоящий
NetworkManager с контролируемым обработчиком: прямой NPE, ReportedException с
ранним CrashReport, сохранность исходного исключения и отсутствие контекста в
следующем постороннем отчёте. Сценарий: `-PserverSmokeScenario=interaction`.
Это искусственная проверка механизма, не повтор исходного AE2 бага.

Новый standalone CLI также проверен на локальной копии исходного отчёта игрока:
сводка улучшена, предмет и контейнер задним числом не выдумываются.

Сценарий interaction прошёл в dev и production reobf server: оба маркера
CONTEXT_PASS wrapped=false/true и NO_STALE_STATE, затем штатная остановка после
120 тиков. Production-проверка выполнена в новом отдельном тестовом мире;
старый мир не подтверждался при предупреждении об отсутствующих AE2-модах.
Логи: build/interaction-server.log, build/interaction-final-check.log;
итоговая сборка: build/interaction-release-build.log. JAR и standalone CLI
с SHA256SUMS.txt находятся в build/release/0.1.0-rc.3/.
Сводка удалённого packet-error не утверждает, что остановился весь сервер:
Minecraft может отключить только проблемное соединение. Остановка указывается
для фатального Ticking memory connection, как в исходном пользовательском ZIP.

## Язык сводки — 0.1.0-rc.4

Убрана двуязычная сводка с русским первым. В окружении отчёта сохраняется
client.language; значение считывается повторно при capture, чтобы учитывать
смену языка после запуска. summary.txt и READ-ME-FIRST.txt используют только
этот язык: ru* — русский, остальные — английский. На dedicated server,
до инициализации клиентских настроек и в старых отчётах используется английский.
Standalone CLI использует язык исходного отчёта, не язык ОС разработчика.
Язык экрана BetterCrashes по-прежнему определяется текущей локализацией игры.

46 тестов на Java 8, включая EN/RU/default, и клиентская opt-in проверка языка
в report.json и ZIP. Логи: build/language-build.log, build/language-client-en.log.

## Удаление исходников после проверки ZIP — 0.1.0-rc.5

Порядок: запись временного ZIP, полное чтение всех записей с проверкой CRC,
размеров и SHA-256 ожидаемого содержимого, атомарная публикация, повторная
проверка готового ZIP, затем удаление исходников этого инцидента. Обычный
Minecraft crash-report в crash-reports остаётся. В каталоге инцидента после
успеха остаются share/<archive>.zip и нулевой служебный .lock.

Удаляются только известные файлы трейсера, полностью включённые в архив,
с неизменившимся содержимым. Пропущенный, слишком большой, изменившийся или
недоступный исходник отменяет очистку исходников. Ссылки не обходятся;
посторонние файлы не удаляются. При отказе записи либо проверки исходники
остаются, предыдущий исправный ZIP не заменяется непроверенной сборкой.
Незавершённые временные исходники также не удаляются без включения в архив.

Готовый архив становится основным хранилищем инцидента. Анализ и CLI читают
данные из ZIP без постоянного распаковывания. Новые файлы анализа или поздний
vanilla-report обновляют этот же архив с сохранением прежних снимков; после
проверки временные исходники снова удаляются. Обычный повтор без изменений
не пересобирает архив. CRC повреждённого старого ZIP останавливает обновление
и очистку. Retention распознаёт архивные инциденты.

Старые инциденты с исходниками очищаются при штатном анализе ограниченными
пакетами maxPendingReports. Уже упакованные инциденты не расходуют этот лимит
и не блокируют обработку следующих. CLI сохраняет общий analysis-index.json
в каталоге reports, не создавая отдельный индекс рядом с каждым ZIP.

Общие рабочие файлы сессии и журналы Minecraft не являются исходниками одного
инцидента: ими продолжают пользоваться последующие captures. Они сохраняют
прежние ограничения размера и retention. Удаление исходников инцидента не
отключает запись следующих ошибок и событий текущей сессии.

54 теста на Java 8, включая отдельные проверки успешной очистки, отказа записи,
неверного CRC, пропущенного большого файла, позднего vanilla-report, повторного
анализа без исходников, retention и ограниченной миграции старых инцидентов.
Production-клиент подтвердил ARCHIVE_ONLY_PASS, сохранение штатных кнопок и
обычного отчёта. Dedicated server подтвердил оба packet-context сценария и
отсутствие переноса старого контекста. CLI дважды проверен на копии исходного ZIP
без распакованных исходников; анализ обновляется, исходники не появляются.
Логи: build/archive-cleanup-*.log; пользовательский модпак не изменяется.

Технические логи и скриншоты находятся в build/support-bundle-*.log и
run/obfuscated/screenshots/support-bundle-ui*.png. Пользовательский модпак
этими прогонами не изменяется. Доработка собрана локально как 0.1.0-rc.2.
